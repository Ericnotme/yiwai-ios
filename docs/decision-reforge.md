# 决策回炉：本地验收原型

接续时间胶囊提交 `8dea63548bad124916e6eca0082c2a3330291e14`，在原 App 的棋谱入口实现。未上传或发布；已上传的 0.3.6(9) 不包含本功能。没有云端服务、AI 诊断、账号导入或系统提醒。

## 当前可用流程

1. 对弈轮到自己时可主动记录一处决策，或在棋谱复盘中记录事后回忆。每盘最多两处，包括跳过；不是每步弹窗。记录保留候选着、理由原文、原局面、原棋谱 ID/走法和记录时机。对弈入口会暂停，完成后可手动继续。
2. 棋理标签由用户选择，默认「暂不归类 / 不适用」，可在详情更正并保留修改历史。当前只支持「将军后检查全部合法应将」，检查移王、吃将军子、挡将。没有自动判断用户犯了什么错；不适用的原局面也可保留理由，但不应勉强归类。
3. 保存后 24 小时到期。棋谱 → 决策回炉 → 记录详情 → 开始到期新题。提前练明确标注，不计到期独立通过。原题重试只有原局面确实存在一步将死时可用，单独标记并不计迁移。
4. 先选起点、终点（必要时选择升变），再「提交首次答案」。提交前没有答案、评分、变化线，待提交走法使用坐标，避免 SAN 的 `#` 提前透露将死。提示先成功写入记录再展示；重启继续同一未提交题目，不清除提示或重新抽题。
5. 首次提交只写一次；显示规则核验及反馈。一次答对只记一次本主题独立通过，两次显示两次，不声称掌握思考习惯、提高 Elo 或棋力。用提示、提前练和原题重试单独保存。
6. 本地时间胶囊 schema 2 完整包含关联记录。原棋谱、备注、PGN、FEN、离线对弈与复盘继续沿用。

## 题源、验证和新颖性边界

`YiwaiPractice/Resources/reforge-puzzles.json` 为本项目 2026-10-21 原创的五个局面，版本 1，按仓库现有 GPL-3.0-or-later 许可发布；未复制第三方题库。每题包含源路径、许可、题目版本、验证口径、提示和解释。所有题均为白方一步将死；包括后象车配合、两种封闭将死结构、兵升变和双车配合。这是同一规则主题的极小题库，不覆盖一般战术、开局、中局或全部误解。

使用项目已绑定的 chess.js 1.4.0 校验 FEN，枚举每一合法首着及其后的合法应将，答案集必须恰好等于所有一步将死着。升变题同时接受升后和升车。原生单元测试及 Node 测试独立调用同一可靠规则库核验；不以语言模型判断代替规则，也不声称已做深度引擎棋力评估。运行时再次校验，坏题不展示。

新题排除：当前能读取的本机棋谱全部快照、原有内置题目及其变化、已记录原局面、本功能已展示的局面。FEN 去重保留棋子、行棋方、王车易位和吃过路兵状态，忽略半回合/全回合计数。先原子保存展示记录，再返回题目；换题目编号或计步数不能变成新题。不能识别用户在其他 App、书籍、已删除历史或其他设备看过什么，不保证人生中从未见过。当前五题全展示后诚实显示「待准备」，不生成替代谜题。

## 数据与时间

`Application Support/YiwaiPractice/decisions-v1.json` 独立原子保存，不迁移或覆盖旧棋谱文件。

- `notes`：原棋谱 ID、原 FEN、原始起始 FEN 与历史、候选着/理由原文、落子前或回忆、时间、跳过、用户标签修订。
- `items`：关联 note、下次到期、独立通过次数、待准备原因。
- `sessions`：关联 item、完整题目版本快照、new/original、开始与原到期时间、当时标签、提示时间、首次答案、提交时间、结果、是否计独立通过。用时由提交减开始计算，包含退出 App 的时间。
- `seen`：局面键、题目 ID/版本、展示时间；`catalog` 为本次可用题库快照；`clockOrigin` 标明设备时钟或测试注入时钟。

到期新题首次无提示答对：第一次从实际完成时间起 +3 天，第二次及以后 +7 天。答错、提示、提前练或原题重试：当前通过次数归零，从实际完成时间起 +1 天；跳过不增加或清空已有通过次数，安排 +1 天。用户改标签重置进度并从修改时间起 +1 天。规则只是第一版安排，不是记忆能力模型。设备时钟由本机提供；回拨早于开始时拒绝提交，未实现跨设备或防作弊时钟。

测试使用注入时间验证跨日，不声称已经真实等待数天。UI 时钟入口只在 DEBUG 且 `-ui-testing` 下可用。自动化使用 `ui-test-*` 数据及临时目录。

## 验收与回滚

验收覆盖：全部答案、合法非答案、FEN 去重、题库用尽、坏题与未归类降级、记录时机/跳过/两处上限、标签更正、原子写失败、重启、首次答案不可覆盖、提示/提前/原题/到期区分、实际完成时间计划、完整导出，以及旧 PGN/FEN/备注/对弈/Stockfish 回归。手机界面证据和实际测试统计见任务目录 `../decision-reforge-2026-10-21/完成报告.md`（完成验收后生成）。

回滚点为 `backup/pre-decision-reforge-20261021`，对应上述基线提交。修改前完整源码备份位于任务 evidence 相邻的 backups 目录。若答案不可靠、提示状态丢失、首答可被覆盖、错误地算独立通过、导出缺字段或旧存储无法读取，不接受本原型，应修复或回退。在实际使用后先导出 schema 2 并单独备份 decisions-v1.json，再切回基线；基线不会展示新记录。不要用 reset --hard 或删除数据覆盖用户后续改动。

真机验收尚需用户安排：本地签名安装到指定测试设备，逐项验证记录/提示/重启/导出、系统文件保存、VoiceOver 和外接键盘全键盘访问。此工作不自动申请新权限、上传构建或替用户启用云服务。
